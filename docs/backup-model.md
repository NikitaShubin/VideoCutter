# Бэкап и обмен разметкой: формат архивов

Два вида zip-архивов с `manifest.json` в корне (`format: "videocutter-backup"`):

- **`backup`** — полный слепок задачи (`resource: task`) или проекта
  (`resource: project`, задачи в папках `task_0/`, `task_1/`, …);
- **`annotations`** — только разметка (`fragments.tsv` + отпечаток медиа);
  видео — лишь по явному запросу (`?media=1`).

Формат свой (с CVAT совпадает только философия: задача/проект, членство
указателем на задаче — см. `project-model.md`). Модуль формата —
`backend/backup_format.py`: чистый stdlib, без Django и обращений к ФС;
семантика папок — харнесс `videocutter/standalone`, состояние процесса —
веб-слой.

## Манифест

```json
{
  "format": "videocutter-backup",
  "format_version": "1.0",
  "kind": "backup | annotations",
  "resource": "task | project | null",
  "task_id": "имя задачи | null",
  "project_id": "id проекта | null",
  "tasks": [{"dir": "task_0", "task_id": "имя"}],
  "media": {"total_frames": 10, "width": 0, "height": 0, "fps": 0.0,
            "roles": {"source": null, "preview": "visualization.mp4"}},
  "created_at": "iso8601"
}
```

Правила чтения (`manifest_problem`):

- чужой `format` — отказ («не архив VideoCutter»);
- версия — только по major: `1.x` читается всегда, `2.0` — отказ с
  подсказкой обновиться; младшие версии внутри major — ок;
- неизвестный `kind`/`resource`, нестроковые `task_id`/`project_id` — отказ;
- **неизвестные поля игнорируются** (старшая версия формата не ломает
  младшего читателя);
- манифест больше 4 МБ (`MANIFEST_MAX_BYTES`) — отказ (анти zip-бомба).

## Состав архивов

Бэкап задачи: `manifest.json` + `task.json` + `fragments.tsv` + все видео
папки. Видео — `ZIP_STORED` (без пережатия), остальное — дефлейт.
Не входят: `exports/` (результаты нарезки — производные, не данные),
точечные временные файлы (`.backup-*`, `.import-*`, `.incoming/`).

Бэкап проекта: `manifest.json` + `project.json` + `task_N/` с полными
слепками задач. Манифест перечисляет **реально попавшие** папки (задача
могла уйти между снапшотом состава и сборкой). Пустой проект — валиден
(`tasks: []`).

Экспорт разметки: `manifest.json` + `fragments.tsv` байт-в-байт как на
диске; если разметки нет — пустой валидный заголовок
(`start\tend\tcomment`), roundtrip работает.

## API

| Метод | URL | Ответ |
|---|---|---|
| GET | `workspaces/<id>/backup` | zip слепка задачи |
| GET | `projects/<pid>/backup` | zip слепка проекта |
| POST | `backups/import?on_conflict=…&project=…` (multipart `file`) | 202 `{kind, id, project_id?/tasks?}` |
| GET | `pairs/<id>/annotations[?media=1]` | zip разметки |
| POST | `pairs/<id>/annotations/import[?force=1]` (multipart `file`) | 200 `{task_id, fragments, position}` |

Все URL — в обоих вариантах, со и без trailing slash.

`on_conflict` (дефолт `rename`): `error` — 409 при совпадении имён,
`rename` — папкам суффиксы `_1`, `_2`, … (показ — исходные имена: дубли
отображаемых имён разрешены, как в CVAT; явное имя из архива не
затирается), `overwrite` — замена на месте. `overwrite` — замена на месте.
Неверное значение — 400. `?project=<pid>` — перепривязка импортируемой
задачи (только архив задачи; у бэкапа проекта — 400, членство из архива);
несуществующий проект — 400.

Привязка задачи при импорте: override → из манифеста (если проект есть
в реестре) → из `task.json` архива (если проект есть) → standalone
(`null`). Валидация импортированного запускается с `join_default=False`:
авто-перевес в `default` решённое членство не меняет.

## Импорт: атомарность

Распаковка — в скрытый от сканера стейджинг `.import-*` в корне
workspace-ов (та же ФС — `os.replace` дешёвый) → правка паспорта →
атомарный переезд в целевую папку. Перезапись существующей задачи —
через удаление **только после успешной распаковки**; любой отказ до
переезда оставляет цель нетронутой, стейджинг вычищается. Осиротевшие
стейджинги (крэш посреди импорта) чистит sweep старше 24 ч; живой процесс
держит путь в памяти и чужому воркеру не мешает.

Проект импортируется целиком в стейджинги до создания контейнера:
конфликт в `error`-режиме не оставляет пустой проект. `project.json`:
поля архива поверх базы, `id` — резолвнутый, пустое имя — `id`,
`created_at` — штамп при отсутствии.

## Временные файлы бэкапа

Архив собирается синхронно целиком до первого байта, затем отдаётся
потоком (`Content-Length` — размер файла). Временный `.backup-*.zip`
живёт в корне workspace-ов (сканер dot-имена не видит) и удаляется
закрытием ответа: успех, обрыв клиентом (обновление страницы
mid-download), ошибка сборки — во всех штатных путях мусор не остаётся.
Падение сервера без закрытия (kill -9) оставляет сироту — её чистит
sweep старше 24 ч при следующей сборке.

## Импорт разметки: сверки

1. kind-гейт: полный бэкап здесь — 400 с подсказкой про
   `POST /backups/import`;
2. отпечаток медиа по числу видимых кадров (`fingerprint_problem`):
   расхождение — 409, `?force=1` обходит **только сверку**;
   нули (индекс не готов / нет в архиве) сверку отключают, а не ронят;
3. строгий парсер (`workspace.parse_fragments_tsv_strict` — рядом с
   терпимым `_read`): UTF-8 без control-символов (NUL молча обрывает
   строки у C-читателей), заголовок `start`/`end`, целые границы
   в `[0, total_frames)` — 400; пересечения (включая касание на общем
   кадре) — 409; позиция — 400. Верхняя граница при неизвестном числе
   кадров (`total_frames=0`) не проверяется — как в PUT;
4. атомарная замена `fragments.tsv` (tmp + `os.replace` рядом с целью),
   потолок — 64 МБ (`FRAGMENTS_MAX_BYTES`).

Диапазоны и отпечаток сверяются по `ws.metadata()` — тому же источнику,
что в PUT `/fragments`. Паспорты задач/проектов импорт разметки не трогает.

## Безопасность имён (`member_problem`)

Блокируется всё, что может выйти за целевую папку: абсолютные пути
(включая `C:`), `..`-переходы, обратные слэши, control-символы, пустые
имена. Директории (`/` на конце) допускаются — распаковка их пропускает.
Дополнительно: имя задачи с точки — 400, `projects` — 400 (реестр, не
задача), плоское видео в корне архива проекта — 400 («это бэкап задачи»),
архив задачи без видео — 400 (архив разметки без видео — 400 с подсказкой
«Импорт разметки»), архив проекта без задач — 400.

## UI

Форма задачи (✎): `⤓ Бэкап` и `⤓ Разметка` — скачивание с откликом
(спиннер на сборке, затем % по Content-Length; файл при скачивании
держится в памяти),
`Импорт разметки…` — заливка архива с XHR-прогрессом в баре формы.
Тулбар редактора: те же `⤓ Разметка` / `Импорт разметки…` / `⤓ Бэкап`
(импорт обновляет модель и позицию с сервера).
Вкладка «Проекты»: `⤓` на строке проекта — бэкап проекта со спиннером,
`Восстановить из бэкапа…` — заливка любого архива (default rename:
совпадающие имена получают суффикс `_1`, для восстановления 1:1 в те же
имена — удалить оригиналы или `?on_conflict=overwrite` по API)
с прогрессом; 202 — файлы записаны, индекс догоняет фоном, список
опрашивается сам.

## Ошибки

400 — битый архив/манифест/разметка/параметры; 404 — нет задачи/проекта;
409 — конфликт имён (`error`), чужой отпечаток, пересечения фрагментов;
507 — кончилось место (текст вместо голого 500, мусор вычищен).
