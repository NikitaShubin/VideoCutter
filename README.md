# ✂️ VideoCutter

Веб-сервис покадровой селекции фрагментов видео с визуализацией работы нейросети.

Предназначен для работы с **видеофайлами** в workspace-ах. Video может быть
один или два:

1. **источник** (source) — видео, из которого вырезаются фрагменты;
2. **превью** (preview, опционально) — ролик, который смотрит оператор
   (например, с наложенным результатом работы нейросети).

Один файл без маркера роли — «нейтральный»: он играет обе роли сразу
(source = preview), как опциональный `--preview` в PyVideoCutter. Роли
кодируются **в имени файла**: загруженным файлам сервис выдаёт
унифицированные имена `source.<ext>` / `preview.<ext>`, а оригинальное имя
становится именем workspace (папки). Например, загрузка `6.avi` и
`6_preview.mp4` сохраняется как `workspaces/6/source.avi` +
`workspaces/6/preview.mp4`. Старые суффиксные имена
(`<base>_source`/`<base>_preview`, а также legacy `_viz`/`_visualization`/`_vis`)
по-прежнему распознаются сканером — это позволяет хранить два видео с
одинаковыми оригинальными именами, а смена ролей — это переименование файлов
(кнопка ⇅ «поменять местами»).

Оператор просматривает **превью** (номера кадров и `total_frames` берутся из
него), отмечает места, где нужно доразметить данные, а из парных кадров
**источника** экспортируются фрагменты (индексы 1:1). Это зачаток Active
Learning: «худшие» для текущей модели данные отбираются вручную и идут на
доразметку.

> Статус: **MVP, stateless**. Архитектурный документ — `docs/architecture.md` в родительском проекте.

## Структура

```
videocutter/
├── videocutter/          # ядро: чистая логика (фрагменты, статус-бар, экспорт) + порты
│   ├── core/             #   «труба»: обработка без внутренней памяти
│   ├── adapters/         #   обвязка: источники кадров и хранилище фрагментов
│   └── standalone/       #   автономная FS-обвязка workspace (пример интеграции)
├── backend/              # Django (без БД): workspace-сканер, кадры, CRUD фрагментов, экспорт
├── frontend/             # React + TypeScript: редактор, покадровая навигация, таймлайн
├── scripts/              # тесты ядра, сверка с легаси-поведением, vc-add.sh
├── tools/                # утилиты (легаси-бэкенд для сверки)
├── workspaces/           # workspace-ы: папки с видео + fragments.tsv (не в git)
├── .github/workflows/    # CI: тесты ядра/API + сборка фронтенда
├── docker-compose.yml    # автономный стек: backend + ui (без БД)
└── pyproject.toml        # Python-пакет ядра
```

## Запуск

### Docker (автономный VC, рекомендуется)

```bash
docker compose up --build
```

- UI: http://localhost:3001
- API: http://localhost:8001/api/v1/

Переменные окружения: `VC_BACKEND_PORT` (8001), `VC_UI_PORT` (3001), `DJANGO_SECRET_KEY`,
а также `VC_JPEG_QUALITY` (78) и `VC_FRAME_SCALE` (0.75) — качество и масштаб JPEG-кадров
по умолчанию.

### Локальная разработка

Backend (Python 3.10+, без БД):

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e .
pip install -r backend/requirements.txt
cd backend
python manage.py runserver 8001
```

Frontend (Node 20+, `node >= 23` для пряжи тестов ядра):

```bash
cd frontend
npm install
npm run dev
```

Dev-фронтенд (Vite) ходит в backend через proxy (переменная `VITE_API_TARGET`).

## Как начать использовать

VC stateless: workspace = **подпапка** в `workspaces/` с видеофайлом (парой) и
(опционально) `fragments.tsv`. БД нет, всё хранится на диске. Экспортированные
фрагменты кладутся в подпапку `exports/` workspace.

1. Добавьте видео в workspace:

   ```bash
   ./scripts/vc-add.sh /path/to/video.mp4            # workspace с именем «video»
   ./scripts/vc-add.sh /path/to/video.mp4 my_project # workspace «my_project»
   ```

   Или вручную положите ролики в `workspaces/<имя_проекта>/`: `source.mp4`
   и `preview.mp4` (или один файл без маркера — нейтральный; суффиксные имена
   `<base>_source`/`<base>_preview` тоже читаются). Каждый workspace — **отдельная папка**.

   Проще всего — прямо в браузере: на странице «Рабочие пространства» нажмите
   **«＋ Добавить видео»**, в форме две строки — **«Источник»** (из него режутся
   фрагменты) и **«Превью»** (что показывается); хотя бы одно поле обязательно.
   Workspace создаётся и **сразу открывается в редакторе**. В списке у задачи
   квадратные кнопки **✎ изменить** и **🗑 удалить**: редактирование ролей,
   переименование и безвозвратное удаление workspace (видео, фрагменты и
   экспорт) — здесь.
   Создание/удаление выполняет автономная FS-обвязка `videocutter/standalone/` —
   ядро о папках не знает, а Django-слой только отдаёт её функции по HTTP
   (образец интеграции в свой контур).
2. Откройте http://localhost:3001 и обновите страницу (F5) — workspace, добавленный
   через скрипт или вручную, появится в списке. Workspace, загруженный через браузер,
   открывается сразу.
3. В редакторе отметьте проблемные диапазоны (см. горячие клавиши).
4. Экспортируйте фрагменты оригиналов (серверный ffmpeg).

### Видео-роли: редактирование задачи из списка

Роли управляются **из списка задач** (модель CVAT: разметка и редактирование
задачи разнесены). У каждой задачи рядом две квадратные кнопки: **✎ изменить**
и **🗑 удалить**. Панель «изменить» позволяет:

- переименовать workspace;
- **Заменить…** файл роли (старый файл этой роли удаляется; загрузка с
  XHR-прогрессом);
- **Убрать** ролевой файл (нельзя удалить единственное видео: workspace
  обязан оставаться с видео);
- **⇅ Поменять местами** источник и превью (технически — переименование файлов);
- если в папке записался «неразмеченный» ролик (нейтральный, не распознанный
  как роль) — строка **«Без роли»** с кнопками **→ источник** / **→ превью**
  для назначения роли без новой загрузки.

Таймлайн ведётся по **видимым** кадрам: битые access unit (пакеты без
картинки) пропускаются без дупликации и заглушек, `total_frames` — число
реально декодируемых кадров. Нестыковки пары не блокируют работу, а
показываются предупреждением (⚠ в списке и редакторе): пропущенные битые
кадры источника/превью и несовпадение числа видимых кадров — такую задачу,
возможно, придётся пересоздать, исправив файлы.

Редактор — только «разметка»: одному файлу оба поля показывают одно и то же
«то же видео». После любой операции роли счётчик кадров пересчитывается по
превью, планировщик кадров пересоздаётся, а токен `video_ver` в URL кадров
меняется — HTTP-кэш браузера не отдаст устаревшие JPEG.

### Ползунки качества и масштаба

В редакторе (тулбар) — ползунки **масштаба** (5–100%) и **качества** (30–95)
показываемых кадров. Применяются мгновенно к новым запросам кадров, а с
[debounce](https://developer.mozilla.org/en-US/docs/Glossary/Debounce) 400 мс
сохраняются в `fragments.tsv` (строка-комментарий `# settings <quality> <scale>`)
и восстанавливаются при следующем открытии. Смена настроек не требует повторного
декодирования: GOP-движок хранит кадры группы сжатыми в **JPEG** под ключом
`(gop, quality, scale)` (~0.1–0.3 МБ/кадр — поэтому даже группы в сотни кадров
вмещаются в память), JPEG нужных параметров берётся из кэша готовым.
В кэше одновременно до 16 групп (лимит `VC_GOP_CACHE_GOPS`);
при переполнении (`VC_GOP_CACHE_MB`, 512 МБ) старые группы вытесняются.
Фоновый префетч идёт за подтверждённым обходом (два шага одного знака):
вперёд `g+1…`, назад — зеркально.

### Форматы и экспорт

- Загрузка проверяется **по содержимому** (PyAV), а не по расширению, поэтому
  подойдут и `m2ts`, `mkv`, `webm`, `avi`, `mov` и т.д. Файловый сканер
  workspace (для видео, положенных вручную) распознаёт расширенный список
  расширений `VIDEO_EXTS`; файлы с нераспознаваемым расширением он не найдёт
  (ограничение сканера, а не ядра).
- Экспортированные фрагменты сохраняются в подпапку **`exports/`** workspace
  (файлы нарезаются из **источника** по индексам кадров 1:1 к превью).
  Во время экспорта кнопка показывает прогресс и работает как **отмена**
  (`POST …/export/cancel`; частичные файлы зачищаются, состояние `cancelled`).
  Повтор без изменений границ пропускается («Экспорт актуален»);
  выход из редактора (Esc) экспорт не останавливает — прогресс подхватывается
  при возврате. Параллельный запуск запрещён (409).

Каждая строка списка — мини-статус-бар **«как если бы файл был открыт»**:
зелёный фон, красные фрагменты, затемнение после сохранённого курсора и белый
маркер позиции (общая с редактором отрисовка `frontend/src/model/statusbar.ts`).
Так по зрительной памяти видно, с какими workspace уже работали, а какие новые.
Для читаемости фон строки приглушён одним полупрозрачным слоем (CSS), при
наведении статус-бар просвечивает ярче. Список отсортирован по времени
последней работы (`fragments.tsv`): недавнее — сверху, обновляется при каждом
возврате из редактора.

VC запоминает кадр, на котором вы завершили редактирование, прямо в
`fragments.tsv` (строка-комментарий `# position <N>`; при её отсутствии — кадр 0)
и возвращает на него при следующем открытии workspace.

## Горячие клавиши

| Клавиша | Действие |
|---------|----------|
| `←/→` (`, / .`) | кадр назад/вперёд |
| `Ctrl+←/→` | на 10 кадров |
| `PageUp/PageDown` | границы фрагментов |
| `Home/End` | край видео |
| `Пробел` | play/pause |
| `0-9` | скорость |
| `R` | направление воспроизведения |
| `J` | прокрутка до ближайшей границы фрагмента (на краю видео направление разворачивается) |
| `Клик по таймлайну` | переход к кадру |
| `F` | полноэкранный режим |
| `Tab` | сохранение пропорций изображения |
| `↑`/`↓` (`[`/`]`) | начало/конец фрагмента |
| `K` (`Ins`) | пара границ (фрагмент) |
| `D/Del` | удалить фрагмент |
| `I` | комментарий к сегменту |
| `Ctrl+Z` / `Ctrl+Shift+Z` / `Z` | undo / redo / redo |
| `E` | экспорт (повтор во время экспорта — отмена) |
| `Esc` | выход из полноэкранного режима |
| `Q` | назад к списку (позиция кадра запоминается) |
| `?` / `H` | справка |

## Режимы навигации

Номер и полоса позиции (statusbar) обновляются **мгновенно** при любом
вводе — кадр загружается асинхронно, с маркером загрузки (спиннер
правый нижний угол), пока `position ≠ shownFrame`.

| Режим | Триггер | Поведение |
|-------|---------|-----------|
| **drain** | одиночный тап `←`/`→` | показывает каждый кадр по пути к целевому; тапы накапливаются в буфер во время загрузки |
| **chase** | удержание стрелки (`e.repeat`, в т.ч. `Ctrl+`) | позиция бежит в реальном времени, экран догоняет, допуская дроп кадров; переход на удержание сразу отменяет накопленный буфер тапов (instant switch) |
| **jump** | клик по таймлайну, `PageUp/Down`, `Home/End`, `Ctrl+→` (одиночный) | загружается ровно целевой кадр, без промежуточных |
| (playback) | пробел | последовательно: кадр показан → следующий, все без пропуска, стоп совпадает с полосой |
| **J** | прокрутка до ближайшей границы | непрерывное воспроизведение от текущей позиции до ближайшего начала/конца фрагмента (края видео включены) в текущем направлении, стоп на границе; на краю видео направление разворачивается, как при проигрывании пробелом |

## Тесты

```bash
# ядро (Js-модель фрагментов)
node scripts/test_fragment_model.mjs

# планировщик кадров (режимы навигации, кэш, воспроизведение)
node scripts/test_frame_scheduler.mjs

# статус-бар (чистая отрисовка, общая с превью списка)
node scripts/test_statusbar.mjs

# ядро (Python)
python3 scripts/test_fragment_core.py

# сверка Python-ядра и JS-модели (легаси — справочно)
python3 scripts/compare_fragments.py --random 50

# Django API (+ GOP-движок кадров; нужен ffmpeg в PATH, иначе эти тесты скипаются)
cd backend && python3 manage.py test
```

Полный набор гоняется в **GitHub Actions** (`.github/workflows/ci.yml`) на каждый push
в `main` и каждый PR: JS-модель, статус-бар, планировщик, Python-ядро, сверка,
Django-тесты (с ffmpeg на раннере) и сборка фронтенда.
